# Элементы приложения GStreamer

Этот модуль содержит внутренние обёртки над `appsrc` и `appsink`: границы между NumPy-массивами Devicelab и GStreamer. Общие инварианты внутреннего GStreamer-слоя описаны в `../README.md`.

## AppSrc

`AppSrc` передаёт валидированные NumPy-буферы из Python в GStreamer. При создании он фиксирует свойство `caps`:

```text
audio/x-raw,format=S16LE,layout=interleaved,rate=<rate>,channels=<channels>
```

`push()` принимает только массив, соответствующий `RawAudioSpec`:

- dtype -- little-endian `numpy.int16` (`S16LE`);
- mono -- форма `(frames,)`;
- несколько каналов -- форма `(frames, channels)`;
- массив содержит хотя бы один frame.

Массив может иметь любую длительность. Перед передачей `AppSrc` разбивает его на GStreamer-буферы длительностью не более 20 мс. Это внутренняя политика, не являющаяся частью API. Каждый chunk сериализуется в C-order, поэтому буфер GStreamer сохраняет interleaved расположение сэмплов.

### Временные метки

`AppSrc` использует формат времени GStreamer и не поручает проставление временных меток самому элементу. PTS и duration каждого буфера вычисляются из суммарного числа успешно переданных frames:

```text
PTS      = pushed_frames * GST_SECOND / rate
duration = end_PTS - PTS
```

Счётчик увеличивается только после `push-buffer` с результатом `OK`. Поэтому последовательные успешные вызовы `push()` образуют непрерывную временную шкалу без накопления ошибок округления длительностей отдельных буферов.

### Буферизация и backpressure

По умолчанию staging-очередь `appsrc` имеет целевую ёмкость 250 мс. Конструктор принимает положительный `max_queue_time_ms` и переводит его в `max-bytes` по фиксированному размеру frame:

```text
max-bytes = frame_size * rate * max_queue_time_ms // 1000
```

| Свойство | Значение по умолчанию обёртки | Политика |
| --- | --- | --- |
| `is-live` | `True` | Источник представляет live-поток, а не конечный файл. |
| `format` | `TIME` | PTS и duration интерпретируются как наносекунды GStreamer. |
| `do-timestamp` | `False` | Использовать PTS, рассчитанные обёрткой. |
| `emit-signals` | `False` | Передавать буферы через синхронный сигнал `push-buffer`, не callbacks. |
| `block` | `True` | Блокировать `push-buffer`, когда очередь достигла `max-bytes`. |
| `max-bytes` | 250 мс PCM | Единственная включённая граница staging-очереди. |
| `max-time` | `0` | Не ограничивать очередь отдельным временным лимитом GStreamer. |
| `max-buffers` | `0` | Не ограничивать очередь числом буферов. |

При `block_when_full=True` медленный downstream создаёт обратное давление: `push()` ожидает освобождения места и не отбрасывает уже принятый звук. При `block_when_full=False` обёртка отключает эту блокировку; вызывающий код должен сам определить допустимое поведение при переполнении. Остановка pipeline или асинхронная ошибка должны разблокировать ожидающий вызов на уровне lifecycle, а не в `AppSrc`.

`push()` возвращает `Gst.FlowReturn` для последнего переданного chunk либо сразу для неуспешного chunk. Это позволяет lifecycle отличать `OK`, `EOS`, `FLUSHING` и ошибки. `push_eos()` отправляет сигнал `end-of-stream` и также возвращает его `Gst.FlowReturn`; это команда завершить входной поток, а не получение состояния.

## AppSink

`AppSink` получает нормализованный поток из GStreamer в pull-режиме. `try_pull(timeout_ms=100)` ждёт sample не более указанного числа миллисекунд. Отрицательный timeout отклоняется с `ValueError`; при истечении timeout возвращается `(None, None)`.

До чтения bytes `AppSink` проверяет caps каждого sample. Допускается только:

```text
audio/x-raw,format=S16LE,layout=interleaved,rate=<spec.rate>,channels=<spec.channels>
```

Непустые fixed caps, структура caps, rate и channels обязательны. Несовпадение с `RawAudioSpec` не меняет форму массива неявно: `AppSink` выбрасывает `GStreamerElementError`.

После успешного отображения буфера в память обёртка копирует данные в независимый NumPy `int16` массив. Mono-данные имеют форму `(frames,)`, многоканальные -- `(frames, channels)`. Пустой буфер возвращает `(None, None)`. Размер непустого буфера обязан быть кратен `RawAudioSpec.frame_size`; отсутствие buffer, ошибка отображения или некратный размер завершаются `GStreamerElementError`.

Второй элемент результата -- временная метка в наносекундах. Если PTS отсутствует (`CLOCK_TIME_NONE`) или segment не может перевести его в running time, он равен `None`. При отсутствии segment возвращается исходный PTS. Массив копируется до снятия отображения с GStreamer-буфера, поэтому его можно безопасно использовать после возврата из `try_pull()`.

| Свойство | Значение | Политика |
| --- | --- | --- |
| `emit-signals` | `False` | Извлекать samples вызовом `try-pull-sample`, а не callbacks streaming thread. |
| `sync` | `False` | Делать sample доступным Python сразу после поступления. |
| `max-buffers` | `1` | Хранить не более одного ожидающего sample. |
| `max-bytes` | `0` | Не добавлять вторую границу по объёму. |
| `max-time` | `0` | Не добавлять вторую границу по времени. |
| `drop` | `True` | При заполнении не доставлять устаревший накопившийся звук. |
| `enable-last-sample` | `False` | Не удерживать дополнительную ссылку на последний sample. |
| `wait-on-eos` | `False` | Не ждать извлечения очереди при EOS. |

Эта малая очередь снижает риск доставки устаревшего аудио, но не заменяет bounded leaky-очередь, требуемую выше по capture audio path. Классификацию и восстановление после отдельных ошибок отображения или malformed buffers определяет lifecycle capture pipeline.
